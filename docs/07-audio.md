# 07. 오디오 디렉션

## 7.1 방향성

**오케스트라 + 칩튠 하이브리드.**

칩튠만 쓰면 레트로 향수에는 맞지만 "화려하다"는 인상을 만들지 못한다.
오케스트라만 쓰면 마계촌의 정체성이 사라진다.

우리의 선택: **멜로디 라인은 칩튠 음색, 하모니와 리듬은 오케스트라.**
FM 신스 리드가 현악 스트링 위에서 울린다. 옛것과 새것이 동시에 들린다.

## 7.2 적응형 BGM

**갑옷 상태에 따라 실시간으로 레이어가 바뀐다.** 같은 곡이 플레이어의 처지를 반영한다.

| 상태 | 레이어 구성 |
|---|---|
| 성유물 갑옷 | 기본 + **성가 코러스 레이어** 추가 (장엄함) |
| 강철 갑옷 | 기본 편성 |
| 속옷 | 저역 필터 (컷오프 800Hz) + **심장박동 저음** 추가 + 코러스 제거 |
| 잔여 30초 | 템포 +12%, 퍼커션 레이어 추가 |
| 보스룸 진입 | **0.3초 무음** → 보스 테마 |

구현: 각 스테이지 BGM은 **4개 스템**(리듬 / 베이스 / 멜로디 / 코러스)으로 분리 출력.
런타임에 게인만 조절하므로 CPU 비용이 거의 없고 이음새가 생기지 않는다.
(퍼커션이 다섯 번째 스템으로 붙는다 — 잔여 30초에만 열린다.)

> **현재 구현 — 음원 파일이 아니라 합성이다.**
> `src/core/bgmPattern.ts` 가 패턴을 정하고 `src/core/bgm.ts` 가 WebAudio 로 낸다.
> 무음인 채로 "화려한가"를 물을 수 없어 임시로 넣은 것이며, 믹스·저역통과·더킹·
> 보스 무음은 전부 최종 설계대로 동작한다. 음원 파일이 생기면 `bgm.ts` 만 바뀐다.
>
> **보스 테마 (캐른).** 스테이지가 3/4 왈츠라면 보스는 **4/4** 다 — 박자가
> 달라야 방이 바뀐 것으로 들린다. 마디를 8스텝으로 늘려 같은 시계에서도
> 느리게 들린다. 화성은 i·i·VI·V 네 마디 순환이고, 반복이 곧 패턴 학습의
> 박자가 된다 (튜토리얼 보스라 복잡할 이유가 없다).
>
> 퍼커션이 **항상 열린다.** 마디 첫 박의 타격은 장식이 아니라 패턴을 세는
> 박자라, 잔여 30초 규칙에 맡기면 정작 필요할 때 없다.
>
> 실측: 스테이지 RMS 0.072 / 저역 0.040 → 보스 RMS 0.141 / 저역 0.114.
> "무겁고 느린 리프" 가 저역 2.8배로 나타난다.
>
> 전환은 크로스페이드가 아니라 **0.3초 무음**이다. 절차적 생성이라 두 곡을
> 동시에 울릴 수 없고, 무음이 오히려 낫다 — 소리가 사라지면 사람은 화면을 본다.
> 7.2 표를 그에 맞게 고쳤다.
>
> 실측 (오프라인 렌더 8초, 4~8초 구간):
>
> | 상태 | RMS | 고역 에너지 | 확인한 것 |
> |---|---|---|---|
> | 강철 | 0.072 | 0.0088 | 루프가 끊기지 않는다 (가청 94.9%) |
> | 성유물 | 0.078 | — | 코러스 층이 붙어 지속음이 늘어난다 (가청 99.9%) |
> | 속옷 | 0.064 | 0.0028 | 저역통과 800Hz — 고역이 68% 줄어든다 |
> | 백골(사망) | 0 | 0 | 완전 무음 |
> | 보스 등장 | 0 | 0 | 0.3초 무음 |

## 7.3 스테이지 음악

| 스테이지 | 방향 | 템포 | 특징 악기 |
|---|---|---|---|
| S1 묘지 | 음산한 왈츠 (3/4) | 96 | 첼레스타, 낮은 현, 종소리 | ← **합성으로 구현됨** |
| S2 마을 | 질주하는 행진 | 148 | 브라스, 타악, 왜곡 리드 |
| S3 종루 | **정박 강조** (4/4) | 120 | 튜블러 벨, 하프시코드, 성가 |
| S4 늪 | 불규칙 (7/8) | 88 | 베이스 클라리넷, 물소리 앰비언트 |
| **S5 갱도** | **소리가 곧 정보** | 92 | 곡괭이 타격음, 레일 삐걱임, 깊은 잔향 |
| S6 감옥 | 긴장의 미니멀 | 132 | 팀파니, 사슬 소리, 무음 구간 |
| **S7 절벽** | **바람이 악기다** | 118 | 윈드 하프, 저역 돌풍, 새된 관 |
| S8 왕좌 | 장엄한 파이프 오르간 | 104 | 오르간, 풀 오케스트라, 합창 |
| 환마계 | 전 스테이지 곡의 **역재생 변주** | — | 원곡을 알아볼 수 있게 |

### S3 종루의 특수 설계

BGM의 4/4 박자가 **게임플레이 타이밍과 동기화**된다.
종이 울리는 순간 = 마디 첫 박. 발판 출현·비르나 패턴이 모두 여기 맞춰진다.

이 스테이지에서 플레이어는 소리로 게임을 하게 된다.
**접근성 대응**: 청각 의존을 완화하기 위해 종 울림마다 화면 가장자리 시각 펄스 (기본 ON, 끄기 가능).

## 7.4 보스 음악

| 보스 | 방향 |
|---|---|
| 캐른 | 무겁고 느린 리프. 튜토리얼답게 단순 | ← **합성으로 구현됨** |
| 노커 | **BGM 이 거의 없다.** 타격음과 잔향만 — 이 보스는 소리로 읽는다 |
| 에일로 | 바람 노이즈가 리듬 파트를 대신한다. 돌풍 전조가 곧 박자 |
| 모르그 & 마그 | 2성부 대위법 — 두 처형인의 테마가 서로 얽힘. 한 쪽 사망 시 한 성부만 남고 왜곡 |
| 비르나 | 스테이지 BGM의 직접 확장. 같은 박자 위에서 강렬해짐 |
| 뮤크 | 머리 처치마다 레이어 제거 → 마지막 머리는 거의 무반주 |
| 갈라드 | **랜슬의 테마를 단조로 변주** — 서사를 음악이 말한다 |
| 아스모데우스 | 4페이즈 각각 다른 악장. 페이즈 전환 시 이음새 없이 전개 |
| 루시안 | 게임 전체 테마의 총집합. 5페이즈 = 5개 스테이지 테마 인용 |

---

> **구현 현황.** 믹싱·더킹·무음·프리로드 판정 로직은 완성돼 있고 테스트로 덮여 있다.
> **음원 파일은 아직 없다.** BGM 과 SFX 155종을 제작하기 전까지는 WebAudio 합성으로
> 대신한다. 파일이 생기면 드라이버(`core/bgm.ts`, `core/sfx.ts`)만 교체하면 된다.
>
> SFX 는 **레이어 명세**(`core/sfxSpec.ts`)로 분리해 두었다. 중요 SFX 는 여러 겹이
> 시차를 두고 쌓여야 하고(7.5), 그 타이밍은 순수 데이터라 테스트로 지킬 수 있다.
> 현재 13종 — 155종 중 M1 에 실제로 울리는 것 전부다.

## 7.5 SFX 설계

### 카테고리별 개수

| 카테고리 | 개수 | 비고 |
|---|---|---|
| 랜슬 동작 | 18 | 발소리(지형별 5종), 점프, 착지, 공격 |
| 무기 | 28 | 7무기 × (발사 / 적중 / 각성 발사 / 소멸) |
| 갑옷 | 8 | 획득, 파괴, 파편 낙하, 백골화 |
| 적 | 42 | 14종 × 3 (등장 / 공격 / 사망) |
| 보스 | 21 | 7보스 × 3 (등장 / 패턴 / 격파) |
| UI | 12 | 메뉴, 선택, 확정, 취소, 결과 |
| 앰비언스 | 16 | 스테이지별 2종 |
| **합계** | **~155** | |

### 중요 SFX 상세

**갑옷 파괴** — 이 게임의 시그니처 사운드.
3개 레이어 합성: ① 금속 파열(고역) ② 저역 임팩트(50Hz sub) ③ 파편 낙하(0.4초 지연 시작)
비주얼 연출과 프레임 단위로 맞춘다. t=0 파열, t=40ms sub, t=180ms 파편.

> **구현 실측** (`src/core/sfxSpec.ts`, 오프라인 렌더):
>
> | 구간 | RMS | 저역 성분 | 읽히는 것 |
> |---|---|---|---|
> | 0~40ms | 0.040 | 0.002 | 고역 금속 파열 |
> | 40~180ms | 0.075 | 0.063 | 저역 임팩트 — 에너지의 84% 가 저역이다 |
> | 180~760ms | 0.008 | 0.002 | 파편이 흩어지며 떨어진다 |
>
> 최대 진폭 0.27 로, 게임 안에서 가장 큰 소리다 (일반 타격의 3.7배).
> 밴드패스가 좁으면 에너지가 깎이므로, 게인은 **필터를 지난 뒤 들리는 크기**
> 기준으로 잡았다. 명세 값만 보면 커 보이는 것이 그래서다.

**사망 (백골화)** — 살점이 벗겨지는 소리는 **일부러 코믹하게.**
원작의 톤이 그랬다. 잔혹하게 만들면 반복 사망이 견디기 힘들어진다.

> 구현에서 이 규칙을 테스트로 못박았다 — **70Hz 아래의 강한 저역을 넣지 않는다.**
> 그 대역이 "무겁고 잔혹한" 소리를 만든다. 대신 미끄러지는 음정(만화적 낙하)과
> 딱딱한 뼈 소리 3연타로 구성했다.

**그림(Grimm) 이륙음** — 플레이어가 조건반사적으로 긴장하도록 **고유하고 날카롭게.**
이 소리가 들리면 즉시 위치를 확인하게 만드는 것이 목표.

> 고유성도 테스트로 지킨다 — **다른 어떤 SFX 도 1400Hz 위로 상승하지 않는다.**
> 겹치는 소리가 있으면 조건반사가 생기지 않는다.
> 월드가 `grimmTookOff` 이벤트를 내보내며(대기 → 추적 전이), 매 틱이 아니라
> 풀리는 순간 한 번만 울린다.

## 7.6 오디오 믹싱

| 버스 | 기본 볼륨 | 비고 |
|---|---|---|
| Master | 100% | |
| BGM | 70% | |
| SFX | 85% | |
| 앰비언스 | 50% | |
| UI | 80% | BGM 덕킹 대상 아님 |

### 덕킹

| 트리거 | 대상 | 감쇠 | 복귀 |
|---|---|---|---|
| 갑옷 파괴 | BGM | -9dB | 0.6초 |
| 사망 | BGM + 앰비언스 | -18dB | 1.2초 |
| 보스 등장 | 전체 | -24dB → 무음 0.3초 | 보스 테마 시작 |
| 마법 발동 | 앰비언스 | -12dB | 1.0초 |

**보스 등장 직전 0.3초 무음**은 가장 저렴하고 강력한 연출 도구다.
소리가 사라지면 사람은 반사적으로 화면에 집중한다.

## 7.7 웹 용량 예산

| 항목 | 포맷 | 비트레이트 | 개당 | 총량 |
|---|---|---|---|---|
| 스테이지 BGM (9곡 × 4스템) | OGG Vorbis | 96kbps | ~1.6MB | 14.4MB |
| 보스 BGM (9곡) | OGG Vorbis | 96kbps | ~0.9MB | 8.1MB |
| SFX (155종) | OGG Vorbis | 64kbps mono | ~25KB | 3.9MB |
| 앰비언스 (16종) | OGG Vorbis | 64kbps | ~180KB | 2.9MB |
| **합계** | | | | **~29.3MB** |

> **현재 로드하는 오디오 파일은 0바이트다.** BGM·SFX 모두 합성이므로 위 예산을
> 아직 한 푼도 쓰지 않았다. 초기 로드 실측 0.17MB 가 그래서 나온다.
> 음원을 넣기 시작하면 로딩 전략(아래)이 그때부터 의미를 갖는다.

### 로딩 전략

| 시점 | 로드 대상 |
|---|---|
| 초기 (첫 플레이까지) | UI SFX + S1 BGM 스템 + 공용 SFX = **~2.8MB** |
| 스테이지 진입 시 | 해당 스테이지 BGM + 앰비언스 + 전용 SFX |
| 보스룸 진입 30초 전 | 보스 BGM 프리로드 (끊김 방지) |
| 백그라운드 | 다음 스테이지 에셋 유휴 시간 프리페치 |

**보스 BGM 프리로드 타이밍이 중요하다.** 보스룸 문 앞에서 로딩으로 멈추면 몰입이 깨진다.
