# 02. 코어 메카닉

> 모든 수치는 **논리 해상도 480×270, 타일 16×16px, 고정 60Hz** 기준이다.
> 수치는 프로토타입(M0)에서 반드시 실측 튜닝한다. 여기 적힌 값은 **출발점**이다.

| 웅크리기 히트박스 | 12×16 px | |
| 발 판정 | 폭 10px, 아래 2px | 모서리 걸침 허용 |

## 2.2 이동

| 항목 | 값 |
|---|---|
| 최대 지상 속도 | 110 px/s |
| 가속 | 900 px/s² (약 7프레임에 최대 속도) |
| 감속 | 1400 px/s² (약 5프레임에 정지) |
| 공중 가속 | **0** — 공중 방향 전환 불가 |
| 방향 전환 딜레이 | 없음 (즉시) |

### 고정 점프 궤도 — 시리즈 정체성

점프한 순간의 수평 속도가 착지까지 유지된다. 공중에서 방향키를 눌러도 궤도는 바뀌지 않는다.

**이것은 버그가 아니라 설계다.** 마계촌의 모든 레벨 디자인이 이 규칙 위에 서 있다.
"뛰기 전에 읽는다"는 사고 과정이 이 게임의 핵심 루프다.

단, 아래 관용 장치로 **불합리한 실패**만 제거한다:

| 장치 | 값 | 목적 |
|---|---|---|
| 코요테 타임 | 5프레임 (83ms) | 발판 끝에서 떨어진 직후 점프 허용 |
| 점프 버퍼 | 6프레임 (100ms) | 착지 직전 점프 입력 예약 |
| 모서리 보정 | 좌우 3px | 머리가 천장 모서리에 걸리면 옆으로 밀어냄 |
| 낙하 그립 | 2프레임 | 발판 끝 밟았을 때 미끄러짐 방지 |

## 2.3 점프

| 항목 | 값 | 결과 |
|---|---|---|
| 점프 초속도 | -420 px/s | |
| 중력(상승) | 1500 px/s² | |
| 중력(하강) | 1750 px/s² | 하강이 빨라 "묵직함" 확보 |
| 최대 낙하 속도 | 480 px/s | |
| 최고 도달 높이 | **62.3 px (3.9 타일)** | M0 실측 |
| 최대 점프 거리 | **62.3 px (3.9 타일)** | M0 실측 |
| 점프 총 체공 | **34프레임 (0.567초)** | M0 실측 |

> **실측 주석 (M0-4).** 위 세 값은 60Hz 고정 틱에서 실제로 시뮬레이션한 결과다.
> 최고 높이는 기획 초안의 해석적 계산(59px)보다 3.3px 높다 — 이륙 틱에 중력을 먹이지
> 않기 때문이고, 그 대신 거리와 체공은 초안 값과 일치한다.
>
> **레벨 디자인 기준은 3타일이다.** 궤도가 덮는 거리는 3.9타일이지만, 그 끝은
> 히트박스 오른쪽 1px 만 발판에 걸치는 지점이다. 타일 격자에서 실제로 안전하게
> 건널 수 있는 간격은 **3타일(48px)** 이고 여유는 14px 다. 4타일(64px)은 넘지 못한다.

### 가변 점프 높이 — 채택하지 않음

버튼을 짧게 눌러 낮게 뛰는 기능은 **넣지 않는다.**
점프가 완전히 예측 가능해야 "뛰기 전에 읽는" 루프가 성립한다.
대신 **낮은 점프가 필요한 구간은 레벨 디자인으로 해결**한다 (천장 높이 조절).

> 이 결정은 M0 프로토타입에서 재검증한다. 테스터 절반 이상이 답답함을 호소하면
> "짧은 점프 = 최고 높이의 60%" 2단 방식을 검토한다.

### 계단·사다리

| 지형 | 처리 |
|---|---|
| 계단 | 8방향 이동, 계단 위에서는 점프 불가 (원작 계승) |
| 사다리 | 상하 이동, 좌우 입력 시 이탈, 사다리 위 공격 가능 |
| 경사면 | **없음** — 픽셀아트 플랫포머에서 경사면은 버그의 온상 |

## 2.4 공격

| 항목 | 값 |
|---|---|
| 발사 딜레이 | 3프레임 (50ms) |
| 후딜 | 8프레임 (133ms), 이동은 가능 |
| 화면 동시 투사체 | **2발** (단검만 3발) — 원작 계승 |
| 연사 간격 | 무기별 상이 ([03. 무기](03-weapons-magic.md) 참조) |

### 8방향이 아닌 3방향

| 입력 | 결과 |
|---|---|
| 공격 | 정면 수평 |
| ↑ + 공격 | **수직 상단** — 원작에서 불가능했던 것 |
| ↓ + 공격 (지상) | 웅크린 자세로 수평 (낮은 적 대응) |
| ↓ + 공격 (공중) | **수직 하단** — 착지 전 견제 |
| 대각선 | 지원 안 함 |

> **왜 상하 공격을 허용했나**
> 원작에서 상하 공격 불가는 "어려움"이 아니라 "부당함"이었다.
> 머리 위 적을 때릴 수 없어 죽는 것은 플레이어의 실수가 아니다.
> 대신 **상단 공격은 후딜 12프레임**으로 늘려 남용을 막는다.

## 2.5 갑옷 시스템 — 게임의 심장

### 3단계 구조

```
[성유물 갑옷] --피격--> [강철 갑옷] --피격--> [속옷] --피격--> 사망
   (선택적)              (기본 상태)         (마지막 기회)
```

| 상태 | 획득 | 피격 시 | 능력 |
|---|---|---|---|
| **성유물 갑옷** | 스테이지당 최대 1개, 보물상자 | 강철로 강등 | 무기 각성 + 성흔 마법 사용 가능 |
| **강철 갑옷** | 기본 시작 상태 | 속옷으로 강등 | 기본 |
| **속옷** | — | **사망** | 이동 속도 +8% (공포 보정) |

**핵심**: 성유물은 상시 유지가 아니라 **1회성 유예 + 파워업**이다.
원작의 "2피격 사망" 긴장을 유지하면서, 잘한 플레이에 화려한 보상을 준다.

### 성유물 갑옷 3종

| 갑옷 | 색 | 성흔 마법 | 무기 각성 방향 |
|---|---|---|---|
| **황금 갑옷** | 금색 + 백색 광휘 | 광휘 (Radiance) | 공격력 중심 |
| **은 갑옷** | 은청색 + 냉기 | 성벽 (Aegis) | 방어·유틸 중심 |
| **수정 갑옷** | 자수정 + 굴절 | 균열 (Rift) | 속도·연사 중심 |

각 갑옷은 **시각적으로 즉시 구분**되어야 한다.
황금은 화면을 밝히고, 은은 서리 입자를 흘리고, 수정은 뒤로 잔상을 남긴다.

### 무적 시간

| 상황 | 무적 |
|---|---|
| 피격 후 | 72프레임 (1.2초), 4프레임 주기 깜빡임 |
| 성유물 획득 직후 | 30프레임 (0.5초) |
| 리스폰 직후 | 90프레임 (1.5초) |

### 낙사

낙사는 갑옷 상태와 무관하게 **즉사**다. 원작 계승.
단, "낙사 직전 구간"은 반드시 화면 하단에 시각 경고(붉은 안개)를 둔다.

## 2.6 라이프 & 컨티뉴

| 항목 | 값 |
|---|---|
| 시작 잔기 | 3 |
| 1UP 획득 | 스테이지당 최대 1개 (숨겨진 위치) |
| 잔기 소진 | 게임 오버 → 컨티뉴 무제한 |
| 컨티뉴 시 시작 지점 | 마지막 체크포인트 |
| 컨티뉴 시 잔기 | 3으로 복구 |
| 컨티뉴 시 무기 | **기본 창으로 초기화** (페널티) |

### 체크포인트

- 스테이지당 **2개** (중간 지점, 보스 직전)
- 보스전 사망 시 → 보스 직전 체크포인트 (보스 러시 반복 없음)
- 체크포인트 통과 = 화면 중앙에 봉화 점화 연출 (1.5초, 스킵 가능)

> **재시작 마찰 제거가 최우선이다.**
> 사망 → 재시작 화면 → 조작 가능까지 **3초 이내**. 이 수치를 지키지 못하면
> 다른 모든 설계가 무의미하다. 로딩·페이드·연출 전부 이 예산 안에서 처리한다.

## 2.7 점수 시스템

원작 계승 + 현대적 목적 부여.

| 획득 | 점수 |
|---|---|
| 잡몹 처치 | 100~500 |
| 보물상자 | 1,000 |
| 노히트 구간 보너스 | 구간당 2,000 |
| 스테이지 클리어 시간 보너스 | 남은 시간 × 50 |
| 성유물 갑옷 유지 클리어 | 10,000 |

점수는 **스테이지별 랭크(S/A/B/C)** 로 환산되어 결과 화면에 표시된다.
전 스테이지 S랭크는 도전 과제 및 스킨 해금 조건이 된다.

> 랭크 경계는 `src/game/results.ts` 의 `RANK_THRESHOLDS` 에 있다 (S 20000 · A 13000 · B 7000).
> **잠정값이다** — 실제 클리어 점수 분포를 본 적이 없다. 시간 보너스가 총점을
> 지배하는 구조라(5분 제한에서 빨리 깨면 14,000점) 실측 후 다시 잡아야 한다.
> m1-gate 의 계측이 첫 클리어 기록을 모은다. → prompts/m1-gate.md

## 2.8 제한 시간

| 항목 | 값 |
|---|---|
| 스테이지 제한 시간 | 5분 (일반 플레이어 클리어 시간의 약 1.7배) |
| 잔여 30초 | BGM 템포 +12% · 퍼커션 층 추가 · **HUD 시계가 붉게 맥동** |
| 시간 초과 | 잔기 1 소모, 체크포인트에서 재시작 |

> 원작의 시간 제한은 학습을 방해할 정도로 빡빡했다.
> 우리는 "탐색은 허용하되 늘어지지는 않는" 선에서 여유를 준다.

> **구현 메모.**
> 시계는 월드가 든다(`World.elapsedTicks`). 화면에 그리는 값과 죽이는 값이
> 갈리면 00:00 인데 안 죽거나 그 반대가 된다. 부활과 이어하기에서 0 으로
> 되감는다 — 안 그러면 시간 초과로 죽은 사람이 되살아나자마자 또 끊긴다.
> 클리어한 뒤에는 시간이 죽이지 않는다.
>
> 제한 시간은 난이도가 조절하는 세 축 중 하나다(종자 8분 · 기사 5분 ·
> 성기사 4분). 세 난이도가 각자의 값에서 실제로 끊기는지 테스트로 고정했다.
>
> **문서와 다른 점 하나** — 원래 "화면 가장자리 붉은 맥동" 이었으나 HUD 시계
> 자체를 붉게 맥동시켰다. 줄어드는 것을 직접 가리키는 편이 읽히고, 화면 전체를
> 물들이면 사망 연출의 채도 하강과 겹친다. 가장자리 비네트가 필요하면 되돌린다.
