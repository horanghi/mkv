# 06. 비주얼 디렉션 — 화려함의 실체

> **"화려하다"는 이펙트를 많이 넣는 것이 아니다.**
> 반응성 · 대비 · 절제된 폭발. 이 세 가지가 화려함의 실체다.
> 상시 화려한 화면은 3분 만에 피로해진다. 우리는 **화려해지는 순간을 설계**한다.

---

## 6.1 기본 규격

| 항목 | 값 |
|---|---|
| 논리 해상도 | 480 × 270 (16:9) |
| 스케일 | 정수 배율만 (1080p = 4x, 1440p = 5x) |
| 타일 크기 | 16 × 16 px |
| 랜슬 스프라이트 | 32 × 32 px |
| 대형 보스 | 최대 160 × 160 px |
| 애니메이션 프레임레이트 | 12fps (캐릭터) / 24fps (이펙트) |
| 팔레트 | 스테이지별 서브팔레트 32색 + 공통 UI 16색 |

### 픽셀 순수주의를 지키지 않는다

정통 픽셀아트는 "모든 픽셀이 그리드에 정렬"을 요구하지만, **우리는 이펙트 레이어에서 이 규칙을 깬다.**

| 레이어 | 픽셀 정렬 |
|---|---|
| 타일 · 캐릭터 · 적 | **엄격 준수** — 서브픽셀 렌더 금지 |
| 파티클 · 광원 · 셰이더 | **자유** — 부드러운 그라디언트, 서브픽셀 이동 허용 |

이 하이브리드가 "모던 픽셀아트"의 정체다. Dead Cells, Blasphemous 모두 같은 선택을 했다.

## 6.2 레이어 구조 (8층)

| # | 레이어 | 패럴랙스 | 내용 | S1 구현 |
|---|---|---|---|---|
| 1 | 스카이 | 0.0 | 그라디언트 + 셰이더 노이즈 (구름/오로라) | ✓ 세로 그라디언트 + 흐르는 구름 띠 |
| 2 | 원경 | 0.10 | 산맥, 성채 실루엣 | ✓ 능선 2겹 |
| 3 | 중경 | 0.35 | 건물, 나무 | ✓ 죽은 나무·납골당 + 도깨비불 |
| 4 | 근경 | 0.60 | 무덤, 기둥 | ✓ 묘비·십자가·기둥 |
| 5 | **게임플레이** | 1.00 | 충돌 타일 — 유일하게 상호작용하는 층 | ✓ |
| 6 | 엔티티 | 1.00 | 랜슬, 적, 투사체, 아이템 | ✓ (적은 아직 그레이박스) |
| 7 | 전경 | 1.40 | 안개, 나뭇가지, 쇠창살 (오클루전) | ✓ 안개 + 나뭇가지 (쇠창살은 보스룸용, 미구현) |
| 8 | 포스트 | — | 셰이더 스택 | ✓ |

### 배경은 파일이 아니라 시드에서 만든다

배경 이미지 한 장이면 초기 로드 8MB 예산의 절반을 먹는다. 능선과 소품을
`src/scenery/` 가 시드에서 생성하고 `src/render/parallax.ts` 가 그린다.
같은 시드면 같은 배경이라 새로고침해도 지형이 바뀌지 않는다.

층마다 반복 폭을 서로 다른 소수(317 · 419 · 523 · 613 · 389 · 700)로 잡았다.
같은 폭이면 여러 층의 이음매가 한 지점에서 겹쳐 세로줄이 보인다.

구름은 셰이더 패스를 하나 더 쓰는 대신 아주 옅은 가로 띠 9개로 만들었다.
카메라와 **시간** 둘 다에 반응하므로 서 있어도 하늘이 흐른다 (초당 3.2px).

**전경 나뭇가지는 HUD 바(24px) 아래에 걸리고 최대 10px 내려온다.**
화면 맨 위에 그리면 HUD 가 통째로 덮어 보이지 않는다 — 처음에 그렇게 만들었다가
캔버스 픽셀을 읽어 보고 알았다.

스테이지 1 에서 가장 높은 발판(타일 행 8)에서 뛰었을 때 랜슬의 머리가 닿는
화면 y 가 38 이고 나뭇가지는 34 까지 오므로 4px 여유가 남는다. 이 관계는
HUD 높이와 스테이지 데이터에서 계산해 테스트로 고정했다 — 더 높은 발판을
놓거나 HUD 를 키우면 테스트가 먼저 걸린다. 오클루전이지 가림막이 아니다.

**규칙**: 게임플레이 층(5)과 다른 층은 **명도로 명확히 분리**한다.
배경은 항상 어둡고 채도가 낮으며, 밟을 수 있는 타일만 밝다.
"이게 발판인가 배경인가"를 헷갈리게 하는 순간 게임은 실패한다.

## 6.3 갑옷 파괴 연출 — 시그니처 모먼트

**이 게임에서 가장 많은 리소스를 투입하는 0.3초.**

### 프레임 단위 타임라인

| 시각 | 이벤트 |
|---|---|
| **t=0ms** | 히트 확정. 히트스톱 시작 — 랜슬·적·투사체·파티클 전부 정지 |
| t=0~40ms | 랜슬 스프라이트 전체 백색 플래시 (additive blend, 알파 1.0→0.6) |
| t=40ms | 갑옷 파편 **24개** 스폰 — 물리 파티클 (초속도 랜덤 120~260 px/s, 회전, 중력 적용) |
| t=40ms | 방사형 섬광 링 생성 — 반경 8px → 96px, 0.14초에 걸쳐 확장하며 페이드 |
| t=40~180ms | 크로매틱 애버레이션 0 → 0.8 → 0 (RGB 채널 최대 3px 분리) |
| t=60ms | 화면 전체 순간 반전 1프레임 (16ms) — 강렬한 임팩트 |
| t=100ms | 카메라 셰이크 시작 — 진폭 6px, 감쇠 300ms, 주파수 28Hz |
| **t=180ms** | 히트스톱 해제. 랜슬 = 속옷 스프라이트, 무적 깜빡임 1.2초 시작 |
| t=180~3000ms | 파편이 지면에 튕기며 정지. 3초 후 페이드아웃 |

### 왜 이렇게까지 하는가

플레이어는 갑옷을 잃었을 때 **좌절**한다. 그 감정을 **감탄**으로 덮어쓴다.
지면에 남은 파편은 "방금 여기서 무슨 일이 있었는지"의 물리적 증거이며,
플레이어가 그 자리를 다시 지나갈 때마다 서사가 된다.

### 사망 연출 (속옷 상태에서 피격)

| 시각 | 이벤트 |
|---|---|
| t=0ms | 히트스톱 250ms |
| t=0~250ms | 랜슬 백골화 — 살점이 벗겨지는 8프레임 애니메이션 (원작 계승) |
| t=250ms | 슬로우모션 0.3배속, 1초 지속 |
| t=250ms | 백골 12조각 분해 — 물리 파티클, 지면에서 굴러다님 |
| t=250ms | 카메라 셰이크 10px, 채도 0으로 하강 |
| t=1250ms | 화면 페이드 → 리스폰 |

**총 소요 1.25초.** 이후 리스폰까지 1.5초 이내.

> **구현 실측** (브라우저에서 프레임 단위로 잰 값):
>
> | 시각 | 관측 |
> |---|---|
> | 233ms | 백골 12조각이 나와 좌우 116px 로 흩어진다 |
> | 250~1250ms | 채도 0.477 → 0.051, 파편이 0.3배속으로 흩날린다 |
> | 1267ms | 검은 페이드가 화면을 다 덮는다 |
> | 1570ms | 부활 — 카메라가 체크포인트로 옮겨가는 것이 가려진다 |
> | 1834ms | 페이드가 걷힌다 |
>
> 슬로우모션은 **파편 물리에만** 건다. 사망 중에는 적도 투사체도 멈추므로
> 화면에서 움직이는 것이 파편뿐이고, 로직 전체를 늦추면 재시작 3초 예산을
> 0.7초 먹는다. 늦춰야 하는 것은 보이는 것이다. [재시작 3초 규칙](02-core-mechanics.md#26-라이프--컨티뉴) 준수.

## 6.4 포스트 프로세싱 스택

렌더 순서대로. 각 항목은 품질 설정에서 개별 토글 가능.

### 1. 발광 마스크 (Emissive Mask)

**핵심 기법.** 일반 컬러 버퍼와 별도로 **발광 채널을 렌더**한다.

```
Pass 1: 씬 → colorBuffer
Pass 2: 발광 오브젝트만 → emissiveBuffer  (화염, 마법, 인광, 눈)
Pass 3: emissiveBuffer → 블룸 → colorBuffer 에 additive 합성
```

이렇게 하면 **밝은 타일이 무의미하게 번지지 않고**, 빛나야 할 것만 빛난다.
픽셀아트에서 전역 블룸을 그냥 걸면 화면이 뿌옇게 뭉개진다. 반드시 마스크 방식으로.

| 파라미터 | 값 |
|---|---|
| 블룸 임계값 | 0.75 |
| 블러 패스 | 3단 가우시안 (다운샘플 1/2, 1/4, 1/8) |
| 강도 | 1.2 |

> **구현 주석 (M1-4).** 임계값 대신 **발광 전용 컨테이너**를 쓴다.
> 빛나야 할 것을 별도 층에 그리므로 밝기로 걸러낼 필요가 없고, 오판도 없다.
> 3단 다운샘플은 그대로다 — 작은 단계일수록 넓게 번지므로 약하게 섞는다.

### 2. 2D 동적 라이팅

**픽셀아트 + 동적 광원 = 가장 비용 효율 높은 화려함.**

| 항목 | 내용 |
|---|---|
| 노멀맵 | 타일셋·캐릭터에 노멀맵 생성 (Aseprite → Laigter 또는 수작업) |
| 광원 타입 | 포인트 라이트 (감쇠 반경, 색상, 강도, 깜빡임) |
| 동시 광원 | 최대 16개 (품질 설정에 따라 8/16/32) |
| 그림자 | 없음 (2D 그림자 캐스팅은 비용 대비 효과 낮음) |

**광원을 발생시키는 것들**: 횃불 무기, 화염 장판, 마법, 보스 공격, 스테이지 앰비언트, 랜슬의 성유물 갑옷.

> **구현 주의 — 앰비언트가 곧 화면 밝기다.**
> 광원 층은 씬 위에 **곱하기**로 얹힌다. 따라서 빛이 닿지 않는 곳의 밝기(앰비언트)가
> 화면 전체의 밝기 상한이고, 광원이 만들 수 있는 최대 대비는 `1 / 앰비언트` 다.
> 앰비언트를 어둡게 잡으면 밤 분위기가 아니라 **아무것도 안 보이는 화면**이 되고,
> 광원의 극적인 효과까지 함께 죽는다.
> 실측: 앰비언트 `0x4a4458`(29%)에서는 배경 실루엣이 전혀 읽히지 않았다.
> S1 은 `0xc4ccd0`(약 79%, 차가운 쪽으로 기울임)을 쓴다. → `src/scenery/stage1.ts`

성유물 갑옷을 입은 랜슬은 **스스로 빛난다.** 어두운 스테이지에서 갑옷이 곧 손전등이 되고,
갑옷을 잃는 순간 **세상이 어두워진다.** 게임플레이와 연출이 같은 방향을 가리킨다.

### 3. 화면 왜곡 (Distortion)

| 용도 | 스테이지 | 구현 |
|---|---|---|
| 열 아지랑이 | S2 화염 주변 | UV offset 노이즈, 강도 0.004 |
| 수중 굴절 | S4 수면 아래 | 사인파 UV + 색수차 |
| 시간 왜곡 | 균열 마법 | 방사형 UV 왜곡 + 잔상 누적 |
| 공간 접힘 | 환마계 | UV 타일링 반복 + 미러 |

### 4. 크로매틱 애버레이션

**상시 적용 금지.** 이벤트 순간에만 짧게.

| 이벤트 | 최대 강도 | 지속 |
|---|---|---|
| 갑옷 파괴 | 0.8 (3px) | 140ms |
| 보스 등장 | 1.2 (5px) | 600ms |
| 마법 발동 | 0.5 (2px) | 200ms |
| 페이즈 전환 | 1.5 (6px) | 800ms |

### 5. 비네트 + 그레인

| 항목 | 값 |
|---|---|
| 비네트 강도 | 0.25 (가장자리 어둡게) |
| 비네트 색 | 스테이지 팔레트에서 파생 |
| 필름 그레인 | 0.03 (거의 안 보이지만 있으면 다름) |

### 6. CRT 스캔라인 (옵션, 기본 OFF)

레트로 취향 사용자를 위한 옵션. 스캔라인 + 배럴 왜곡 + 형광체 마스크.

## 6.5 게임필 — 반응성이 곧 화려함

| 이벤트 | 히트스톱 | 셰이크 | 파티클 | 기타 |
|---|---|---|---|---|
| 투사체 발사 | — | — | 총구 섬광 3 | 무기별 광원 펄스 |
| 적 피격 | 20ms | — | 4 파편 | 백색 플래시 2f |
| 잡몹 처치 | 40ms | — | 8 파편 | 처치 링 확산 |
| 대형 적 처치 | 90ms | 3px | 16 파편 | 짧은 화이트아웃 |
| **갑옷 파괴** | **180ms** | **6px** | **24 파편** | 섬광 링 + 색수차 |
| **사망** | **250ms** | **10px** | **12 백골** | 슬로우 0.3x 1초 |
| 보스 페이즈 전환 | 200ms | 8px | — | 화면 전환 컷 0.8초 |
| **보스 격파** | **400ms** | **14px** | **전 화면** | 화이트아웃 → 슬로우 2초 |
| 마법 발동 | 120ms | 4px | 화면 전체 | 셰이더 오버레이 |
| 체크포인트 | — | 2px | 봉화 상승 | 광원 확산 |

### 히트스톱 구현 주의

히트스톱 중에도 **다음은 계속 갱신**된다:
- 입력 버퍼 수집 (플레이어가 눌렀는데 씹히면 안 됨)
- UI 애니메이션
- 히트스톱 자체의 타이머

정지하는 것: 물리, 엔티티 AI, 애니메이션 프레임 진행, 투사체 이동.

### 카메라

| 항목 | 값 |
|---|---|
| 추적 방식 | 데드존 + 부드러운 보간 (lerp 0.12) |
| 데드존 | 가로 64px, 세로 40px |
| 선행 (Look-ahead) | 이동 방향으로 최대 32px |
| 낙하 시 | 세로 데드존 확대 (착지점을 미리 보여줌) |
| 셰이크 | 펄린 노이즈 기반, 진폭 감쇠 곡선 ease-out |

## 6.6 스테이지별 팔레트

인접 스테이지끼리 색상환에서 최대한 멀리 배치했다.

| 스테이지 | 주색 | 보조색 | 강조색 | 인상 |
|---|---|---|---|---|
| S1 묘지 | `#1a2f2e` 청록 (180°) | `#2d4a52` | `#a86ff2` 보라 인광 | 차갑고 습함 |
| S2 마령촌 | `#3d1408` 암적 (15°) | `#8a2b0c` | `#ffb340` 황금 화염 | 뜨겁고 급함 |
| S3 종루 | `#dae8f0` 백청 (210°) | `#7a9bb5` | `#e8f7ff` 은빛 | 밝고 날카로움 |
| S4 늪 | `#1f2a12` 독녹 (90°) | `#3d4a1f` | `#b84ade` 자주 | 탁하고 불길함 |
| **S5 갱도** | `#140f0a` 흑갈 (**거의 무채색**) | `#241a12` | `#7fe0a8` 인광 이끼 | 보이지 않음 |
| S6 감옥 | `#0d0814` 흑자 (280°) | `#241a35` | `#ffffff` 번개 | 어둡고 극단적 |
| **S7 절벽** | `#22323c` 창백한 청회 (195°) | `#3f5a68` | `#ffe8a3` 창백한 햇빛 | 높고 사납다 |
| S8 왕좌 | `#2b0510` 심홍 (345°) | `#5c0a1a` | `#f0c04a` 흑금 | 장엄하고 무거움 |
| ★ 환마계 | **HSV 반전** | — | — | 낯설고 불쾌함 |

**8스테이지에서는 색상환 규칙이 느슨해진다.** 6개일 때는 "최대한 멀리"가
가능했지만 8개는 바퀴가 좁다. 규칙을 **인접 90° 이상**으로 바꾸고, 그것도
안 되는 자리는 **명도와 채도로** 벌린다.

**S5 갱도는 이 규칙 밖이다.** 색으로 구분하지 않고 **빛의 부재**로 구분한다 —
화면에서 밝은 것은 플레이어가 들고 있는 빛뿐이고, 인광 이끼만이 발판 윤곽을
남긴다. 색상환에 자리를 잡을 필요가 없는 유일한 스테이지다.

### S1 팔레트를 실제로 어떻게 나눠 썼는가

| 색 | 쓰임 |
|---|---|
| 주색 `#1a2f2e` 청록 | 하늘 — 실루엣이 등질 배경. 실제 값은 이 계열을 밝힌 `#3a6b6e` |
| 보조색 `#2d4a52` | 밟을 수 있는 타일 (`#33565f`), 윗면 강조 `#6d9dab` |
| 강조 `#a86ff2` 보라 인광 | **도깨비불에만.** 발광 마스크를 타고 블룸까지 가므로 여러 곳에 쓰면 화면이 보라색으로 뜬다 |

실루엣 4층은 주색을 단계적으로 어둡게 한 것이다. 하늘을 등지고 **가까워질수록 어둡다** —
그래야 네 층이 겹쳐도 앞뒤가 읽힌다.

**명도 순서** (검증됨 — `src/scenery/stage1.test.ts`):
발판 윗면 > 발판 > 하늘 > 원경 > 성채 > 중경 > 근경.
하늘이 발판보다 밝은 것은 의도다 — 하늘은 화면 위쪽에만 있어 발판과 맞닿지 않으므로
헷갈릴 일이 없고, 밝아야 실루엣이 읽힌다.

**S3의 역할**: 8개 스테이지 중 유일하게 **밝은** 스테이지.
어두운 스테이지가 연속되면 화려함이 무뎌진다. 대비를 위한 의도적 배치다.

## 6.7 환마계 비주얼 — 셰이더로 만드는 두 번째 게임

2회차는 **에셋을 거의 추가하지 않고** 완전히 다른 인상을 만든다.

| 기법 | 효과 |
|---|---|
| HSV 색상 반전 | 청록 묘지 → 주황 묘지. 같은 타일인데 다른 장소로 보임 |
| 명도 반전 | 밝은 부분이 어두워짐. 공간 인지가 뒤틀림 |
| UV 미러링 | 배경 레이어를 좌우 반전 — "익숙한데 틀린" 느낌 |
| 잔상 누적 | 프레임 블렌딩으로 모든 움직임에 잔상 |
| 스캔 왜곡 | 8초마다 화면에 수평 글리치 라인이 흐름 |
| 파티클 반전 | 낙하 파티클이 위로 올라감 |

**개발 관점의 가치**: 스테이지 6개의 아트 비용으로 12개 분량의 인상을 만든다.
웹 플랫폼의 용량 제약을 정면으로 해결하는 설계다.

## 6.8 UI 비주얼

| 항목 | 방향 |
|---|---|
| 폰트 | 픽셀 비트맵 폰트 (한글 8×8 / 12×12 2종 제작 필요) |
| HUD 위치 | 상단 좌측(잔기·무기) / 상단 우측(시간·점수) |
| HUD 스타일 | 반투명 없음. 픽셀 프레임 + 단색 배경 |
| 애니메이션 | 값 변화 시 숫자 롤링 + 짧은 스케일 펀치 |
| 갑옷 표시 | HUD가 아니라 **랜슬 스프라이트 자체**로 전달 |

**갑옷 상태를 HUD에 숫자로 표시하지 않는다.**
플레이어는 화면 구석이 아니라 자기 캐릭터를 봐야 한다.
갑옷 상태가 시각적으로 명백하다면 게이지는 불필요하다.

### 품질 3단계 자동 감지

| 등급 | 조건 | 비활성화 항목 |
|---|---|---|
| **낮음** | 30fps 미만 3초 **또는** 50fps 미만 10초 | 동적 라이팅, 블룸, 왜곡, 그레인 |
| **보통** | 기본값 | 왜곡 감소, 파티클 400 |
| **높음** | 60fps 안정 5초 | 전부 활성 |

> **강등 조건이 둘인 이유.** 30fps 규칙만 두면 35~49fps 로 *계속* 도는 기기가
> 사각지대에 남는다 — m1-gate 의 60fps 유지율은 프레임 20ms(=50fps) 이하를
> 세므로 그런 기기는 유지율이 0 에 가까운데도 화질이 내려가지 않는다.
> 2차 규칙은 그 구간만 구제하되 **10초로 훨씬 느리게** 반응한다. 잠깐의
> 하락에 화면이 오르내리면 "죽는 연출" 인상이 나빠지고 그것도 게이트 항목이다.
> → `src/fx/quality.ts` · `src/telemetry/frames.ts`

> **프레임 실측** (스테이지 1 보스룸 — 배경 5층 + 적 10 + 보스 + 블룸 + 광원,
> `gl.finish()` 로 GPU 완료까지 포함):
>
> | 화질 | median | p95 | max |
> |---|---|---|---|
> | 낮음 | 0.6ms | 1.5ms | 8.2ms |
> | 보통 | 0.6ms | 0.8ms | 1.3ms |
> | 높음 | 0.6ms | 1.5ms | 7.5ms |
>
> 예산 16.67ms 대비 p95 가 9% 다. 세 등급의 차이가 거의 없는 이유는
> 스테이지 1 에 광원이 둘뿐이고 파티클 상한에 닿지 않기 때문이다 —
> 등급 차이가 드러나는 것은 S2 이후다.
>
> **측정 방법 주의.** `gl.finish()` 없이 프레임을 연속으로 돌리면 GPU 큐가
> 적체되어 높음에서 p95 13ms 같은 값이 나온다. 그건 렌더 비용이 아니라
> vsync 없이 몰아친 결과다. 실기 60fps 유지율은 여전히 사람이 재야 한다
> (브라우저 패널은 rAF 를 멈춘다). → prompts/m1-gate.md

플레이 중 자동 전환 시 **한 번만 조용히 토스트로 안내**하고, 이후 수동 설정을 존중한다.
